Association Rules & Collaborative Filtering

“Customers who bought this also bought…” comes in two flavours. Association rules find items that go together across many transactions; collaborative filtering finds people (or items) that resemble each other and recommends accordingly. Both power the recommendation engines you use every day.

Concept map

Rules and the three numbers that judge them

An association rule has the form IF antecedent THEN consequent (A ⇒ C), where A and C are disjoint sets of items. With N transactions:

MeasureFormulaQuestion it answers
Support\(\frac{\#(A \cup C)}{N}\)How often does the whole rule occur? (Is it worth caring about?)
Confidence\(\frac{\#(A \cup C)}{\#A} = \hat P(C \mid A)\)When A is bought, how often is C bought too?
Lift\(\frac{\text{confidence}}{\#C / N} = \frac{\hat P(C\mid A)}{\hat P(C)}\)Is C more likely with A than in general? (> 1 = positive association)

Try IF {Red, White} THEN {Green}: support 0.2, confidence 0.5, lift 2.5. Green appears in only 20% of all baskets but 50% of red-and-white ones. Then try IF {White} THEN {Red}: support 0.4, but lift 0.95, which is no better than chance. Highlighted rows contain the antecedent; bold ones contain the whole rule.

A rule “IF bread THEN milk” has confidence 0.80. 80% of all baskets contain milk. Is this a useful rule?

C. High confidence can simply reflect a popular consequent. Lift corrects for the base rate, and that is why it is the first column to sort by.

Finding rules: the Apriori algorithm

With k items there are \(3^k - 2^{k+1} + 1\) possible rules: about 57,000 for just 10 items. Apriori avoids enumerating them all:

  1. Choose a minimum support. Find all frequent single items.
  2. Build candidate 2-itemsets only from frequent 1-itemsets, count them, keep the frequent ones; then 3-itemsets from frequent 2-itemsets, and so on. This works because any subset of a frequent itemset must itself be frequent (the Apriori property), so infrequent branches are pruned early.
  3. From each frequent itemset, generate rules that meet a minimum confidence.
  4. Sort by lift; inspect, de-duplicate and judge them with domain knowledge.

Beware of rule explosions

Real retail data produce thousands of rules, many redundant (A,B ⇒ C alongside A ⇒ C) and some spurious by chance alone. Require meaningful support, look at lift, and validate surprising rules on a holdout set of transactions.

Collaborative filtering

Association rules use baskets; collaborative filtering (CF) uses user × item ratings or purchases, and makes personalised recommendations.

User-based CF

Find users most similar to the target user (correlation or cosine similarity over co-rated items), then recommend what they liked. This is kNN on users.

Item-based CF

Find items similar to the ones the user already liked (based on who rated them alike). It scales better and is the approach popularised by Amazon.

Predict a rating with user-based CFcourserating.csv: 15 students × 9 courses (1–4 stars)

Similarity = cosine on the courses both students rated. The prediction is the similarity-weighted average of the k most similar students who rated the target course. Notice how sparse the matrix is: most cells are empty, and some students share almost no courses with anyone. This is the cold-start problem.

A brand-new student has rated nothing yet. What can user-based CF recommend?

A. That is the cold-start problem. Real systems blend CF with content-based features and popularity.

import pandas as pd
from mlxtend.frequent_patterns import apriori, association_rules
fp = pd.read_csv("data/Faceplate.csv").set_index("Transaction").astype(bool)
print(fp.mean())                                   # item supports
itemsets = apriori(fp, min_support=0.2, use_colnames=True)
rules = association_rules(itemsets, metric="confidence", min_threshold=0.5)
print(rules.sort_values("lift", ascending=False)[["antecedents", "consequents", "support", "confidence", "lift"]].head(6))

import numpy as np
cr = pd.read_csv("data/courserating.csv", index_col=0)
def cosine(u, v):
    both = cr.loc[u].notna() & cr.loc[v].notna()
    if both.sum() == 0: return np.nan
    a, b = cr.loc[u, both], cr.loc[v, both]
    return float(a @ b / (np.linalg.norm(a) * np.linalg.norm(b)))
def predict(user, item, k=3):
    raters = cr.index[cr[item].notna() & (cr.index != user)]
    sims = pd.Series({v: cosine(user, v) for v in raters}).dropna().nlargest(k)
    return (sims * cr.loc[sims.index, item]).sum() / sims.sum(), sims.round(3).to_dict()
print(predict("EN", "Python"))

Common pitfalls

  • Sorting by confidence alone: popular consequents dominate. Sort by lift and check support.
  • Too-low support produces thousands of rules driven by a handful of transactions.
  • Reading rules causally: “IF diapers THEN beer” does not mean diapers cause beer purchases.
  • Ignoring sparsity and cold start in CF.
  • Cosine on raw ratings treats a harsh rater and a generous one as different; mean-centre ratings (or use Pearson correlation) to fix it.
