k-Nearest Neighbors

The simplest learner of all has no equation: to classify a new record, find the k most similar records you already know and let them vote. That simplicity hides two decisions that make or break it, how to measure “similar” and how many neighbours to ask.

~70 minTextbook ch. 7

Concept map

The algorithm

  1. Choose a distance measure and a number of neighbours k.
  2. For a new record, compute its distance to every training record.
  3. Take the k nearest.
  4. Classification: predict the majority class (or report the class proportion as a probability and apply a cutoff). Prediction: predict the average (or distance-weighted average) of their Y values.

kNN is nonparametric and lazy: there is no fitting step and no coefficients, and all the work happens at prediction time. It can follow very irregular boundaries, but it needs lots of data, struggles with many predictors (the “curse of dimensionality”) and is slow to score huge datasets.

Distance and why scaling is mandatory

The default is Euclidean distance between records \(\mathbf{x}\) and \(\mathbf{u}\):

\[ d(\mathbf{x}, \mathbf{u}) = \sqrt{(x_1 - u_1)^2 + (x_2 - u_2)^2 + \cdots + (x_p - u_p)^2} \]

Squared differences add up across variables, so a variable measured in large units dominates. In the riding-mower data, income ranges over about $33k–$110k while lot size ranges over 14–24 thousand ft². Unscaled, “nearest” almost only means “similar income”.

Choosing k

Small k (e.g. 1)

Very flexible; follows local noise. Low bias, high variance: overfits.

Large k (up to n)

Very smooth; at k = n it always predicts the majority class. High bias, low variance: underfits.

Choose k by cross-validated performance, just like the polynomial degree in Lecture 3. Odd values avoid ties in two-class problems. On Universal Bank, 10-fold CV accuracy by k:

kNN with k = 1 is evaluated on its own training data. What accuracy will it report?

100%. Each training point’s nearest neighbour is itself. This is the purest example of why training error says nothing about predictive performance.

Code walk: kNN for loan acceptance

Data: UniversalBank.csv (prepared as in Lecture 4).

Stratified split

library(caret)
bank <- read.csv("data/UniversalBank.csv")[, -c(1, 5)]          # drop ID and ZIP
bank$Education <- factor(bank$Education, labels = c("Undergrad", "Graduate", "Advanced"))
bank$Personal.Loan <- factor(bank$Personal.Loan, labels = c("No", "Yes"))
set.seed(1)
idx <- createDataPartition(bank$Personal.Loan, p = 0.6, list = FALSE)   # keeps 9.6% in both
train <- bank[idx, ]; valid <- bank[-idx, ]

import pandas as pd
from sklearn.model_selection import train_test_split
bank = pd.read_csv("data/UniversalBank.csv").drop(columns=["ID", "ZIP Code"])
bank["Education"] = pd.Categorical(bank["Education"].map({1: "Undergrad", 2: "Graduate", 3: "Advanced"}),
                                   categories=["Undergrad", "Graduate", "Advanced"])
X = pd.get_dummies(bank.drop(columns="Personal Loan"), drop_first=True, dtype=int)
y = bank["Personal Loan"]
X_train, X_valid, y_train, y_valid = train_test_split(X, y, test_size=0.4, random_state=1, stratify=y)

Standardise inside CV, tune k

ctrl <- trainControl(method = "cv", number = 10)
knn_fit <- train(Personal.Loan ~ ., data = train, method = "knn",
                 preProcess = c("center", "scale"),        # learned on each training fold
                 tuneGrid = data.frame(k = seq(1, 19, 2)), trControl = ctrl)
knn_fit; plot(knn_fit)

from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.neighbors import KNeighborsClassifier
from sklearn.model_selection import GridSearchCV, StratifiedKFold
pipe = make_pipeline(StandardScaler(), KNeighborsClassifier())     # scaler fit within each fold
grid = GridSearchCV(pipe, {"kneighborsclassifier__n_neighbors": list(range(1, 21, 2))},
                    cv=StratifiedKFold(10, shuffle=True, random_state=1), scoring="accuracy")
grid.fit(X_train, y_train)
print(grid.best_params_, round(grid.best_score_, 4))
What you should see: best k = 3 (or nearby) with CV accuracy ≈ 0.96. Accuracy declines slowly as k grows.

Validate, and compare with no scaling

pred <- predict(knn_fit, valid)
confusionMatrix(pred, valid$Personal.Loan, positive = "Yes")
prob <- predict(knn_fit, valid, type = "prob")[, "Yes"]   # share of neighbours voting Yes

from sklearn.metrics import confusion_matrix, recall_score, accuracy_score
pred = grid.predict(X_valid)
print(accuracy_score(y_valid, pred), recall_score(y_valid, pred)); print(confusion_matrix(y_valid, pred))
raw = KNeighborsClassifier(n_neighbors=3).fit(X_train, y_train).predict(X_valid)   # no scaling
print("unscaled:", accuracy_score(y_valid, raw), recall_score(y_valid, raw))
What you should see: standardised: accuracy ≈ 0.96, sensitivity ≈ 0.62. Unscaled: accuracy ≈ 0.90, sensitivity ≈ 0.35. Same algorithm, same k.

Common pitfalls

  • Not standardising, or standardising with validation-set statistics.
  • Using many irrelevant predictors. Every extra dimension dilutes the distance. Select variables first (L6) or reduce dimension (L7).
  • Choosing k on training accuracy (always k = 1).
  • Raw categorical codes in distances: use dummies, which also need sensible scaling.
  • Expecting speed. Scoring compares with every training record; large n means slow predictions.
