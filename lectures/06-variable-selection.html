Variable Selection & Regularization

More predictors are not always better: each one adds variance, cost and a chance to overfit. Today we compare two ways to keep a model lean: searching for a good subset of variables, and shrinking all coefficients toward zero with a penalty.

~75 minTextbook ch. 6.4ISLR ch. 6

Concept map

Why use fewer predictors?

  • Variance. Every estimated coefficient carries noise. Irrelevant predictors add noise to predictions without adding signal.
  • Multicollinearity. Correlated predictors make coefficients unstable (remember Age vs. Experience in Lecture 4).
  • Cost and robustness. Every variable must be collected, cleaned and kept available in production.
  • Interpretability. A 7-variable model can be explained to a manager; a 70-variable one cannot.

This is the bias–variance trade-off: dropping a weak predictor adds a little bias but can remove more variance, lowering error on new data.

\[ \text{Expected prediction error} = \text{Bias}^2 + \text{Variance} + \text{irreducible noise} \]

With 19 candidate predictors, how many models does exhaustive search fit?

2¹⁹ = 524,288. Feasible on a laptop for linear models, but double the predictors and it becomes 275 billion. Greedy searches (forward/backward/stepwise) are the practical substitute, with no guarantee of finding the best subset.

Shrinkage: ridge, lasso and elastic net

Instead of in-or-out decisions, regularization keeps all predictors but penalises large coefficients. With standardised predictors it minimises

Standardise first

The penalty adds up coefficient sizes, so a predictor measured in kilometres (tiny β) and one in years (large β) would be penalised unequally. glmnet standardises internally; in scikit-learn put a StandardScaler in a pipeline.

Choosing λ

λ is a tuning parameter: chosen by cross-validation, never by training error (which always prefers λ = 0). Two common rules:

  • λmin: the value with the lowest mean CV error.
  • λ1se: the largest λ whose CV error is within one standard error of the minimum, giving a simpler model that is statistically just as good.

On the Toyota data (1,436 cars, 60% training) the results are instructive:

Regularization barely beat OLS here. Why might that be?

B. Shrinkage shines when p is large relative to n or predictors are highly correlated. Here its real payoff is the 7- to 13-variable models that predict almost as well as the 19-variable one: cheaper and easier to explain.

Code walk: lean models for car prices

Data: ToyotaCorolla.csv (all 1,436 cars).

Prepare, and fix a data error

car <- read.csv("data/ToyotaCorolla.csv")
car$CC[car$CC == 16000] <- 1600                 # a typo: one car listed at 16,000 cc
vars <- c("Price", "Age_08_04", "KM", "Fuel_Type", "HP", "Met_Color", "Automatic", "CC",
          "Doors", "Quarterly_Tax", "Weight", "Mfr_Guarantee", "Guarantee_Period", "Airco",
          "Automatic_airco", "CD_Player", "Powered_Windows", "Sport_Model", "Tow_Bar")
car <- car[, vars]; car$Fuel_Type <- factor(car$Fuel_Type)
set.seed(1); idx <- sample(nrow(car), 0.6 * nrow(car))
train <- car[idx, ]; valid <- car[-idx, ]
rmse <- function(fit, newx = valid) sqrt(mean((valid$Price - predict(fit, newx))^2))

import pandas as pd, numpy as np
from sklearn.model_selection import train_test_split, KFold
car = pd.read_csv("data/ToyotaCorolla.csv")
car.loc[car["CC"] == 16000, "CC"] = 1600         # a typo: one car listed at 16,000 cc
cols = ["Age_08_04", "KM", "Fuel_Type", "HP", "Met_Color", "Automatic", "CC", "Doors",
        "Quarterly_Tax", "Weight", "Mfr_Guarantee", "Guarantee_Period", "Airco",
        "Automatic_airco", "CD_Player", "Powered_Windows", "Sport_Model", "Tow_Bar"]
X = pd.get_dummies(car[cols], drop_first=True, dtype=int); y = car["Price"]
X_train, X_valid, y_train, y_valid = train_test_split(X, y, test_size=0.4, random_state=1)
cv = KFold(10, shuffle=True, random_state=1)
rmse = lambda m, Xv=X_valid: np.sqrt(((y_valid - m.predict(Xv))**2).mean())
Why the fix matters: leave the 16,000 cc typo in and, depending on which partition it lands in, validation RMSE can more than double. Exploring first (Lecture 1) pays off.

Stepwise / forward selection

full <- lm(Price ~ ., data = train)
null <- lm(Price ~ 1, data = train)
step_fit <- step(null, scope = formula(full), direction = "both", trace = 0)  # AIC-based
formula(step_fit); rmse(step_fit)

from sklearn.linear_model import LinearRegression
from sklearn.feature_selection import SequentialFeatureSelector
sfs = SequentialFeatureSelector(LinearRegression(), n_features_to_select="auto", tol=10,
                                direction="forward", cv=cv, scoring="neg_root_mean_squared_error")
sfs.fit(X_train, y_train)
sel = X.columns[sfs.get_support()]; print(list(sel))
fwd = LinearRegression().fit(X_train[sel], y_train); print(rmse(fwd, X_valid[sel]))
What you should see: Python’s forward search (stop when CV RMSE improves by < €10) keeps 7 predictors: Age, KM, HP, Quarterly_Tax, Weight, Automatic_airco, Powered_Windows. R’s AIC stepwise keeps more, because AIC is a gentler stopping rule.

Lasso and ridge with cross-validated λ

library(glmnet)
x_train <- model.matrix(Price ~ ., train)[, -1]; x_valid <- model.matrix(Price ~ ., valid)[, -1]
cv_lasso <- cv.glmnet(x_train, train$Price, alpha = 1, nfolds = 10)
plot(cv_lasso)                                    # CV curve with lambda.min and lambda.1se
coef(cv_lasso, s = "lambda.1se")                  # zeros = dropped variables
sqrt(mean((valid$Price - predict(cv_lasso, x_valid, s = "lambda.min"))^2))
cv_ridge <- cv.glmnet(x_train, train$Price, alpha = 0)
plot(cv_ridge$glmnet.fit, xvar = "lambda")        # ridge paths: shrink, never zero

from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LassoCV, RidgeCV, Lasso
lasso = make_pipeline(StandardScaler(), LassoCV(cv=cv, max_iter=50000)).fit(X_train, y_train)
L = lasso[-1]; print("lambda_min:", L.alpha_, " RMSE:", rmse(lasso))
mse, se = L.mse_path_.mean(1), L.mse_path_.std(1) / np.sqrt(10)          # 1-SE rule by hand
a1se = L.alphas_[np.where(mse <= mse.min() + se[mse.argmin()])[0][0]]
lasso1se = make_pipeline(StandardScaler(), Lasso(alpha=a1se, max_iter=50000)).fit(X_train, y_train)
coefs = pd.Series(lasso1se[-1].coef_, index=X.columns); print(coefs[coefs != 0].round(0))
ridge = make_pipeline(StandardScaler(), RidgeCV(alphas=np.logspace(-2, 4, 60))).fit(X_train, y_train)
print("ridge RMSE:", rmse(ridge))
What you should see: lasso at λmin keeps every predictor (RMSE ≈ €1,120); at λ1se it drops 6 and RMSE rises only ~4%. Age always has by far the largest standardised coefficient.

Common pitfalls

  • Forgetting to standardise before ridge/lasso in scikit-learn.
  • Choosing λ or the subset on the validation set and then reporting validation error as if it were unbiased. Use CV inside the training data, then validate.
  • Trusting p-values after stepwise selection. They ignore the search and are far too optimistic.
  • Interpreting lasso’s choice among correlated predictors as meaningful. Rerun with a different seed and another one may be picked.
  • Penalising the intercept or dummy reference levels incorrectly: let the library handle the intercept.
