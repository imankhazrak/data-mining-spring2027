Classification & Regression Trees

A decision tree asks one yes/no question at a time until the answer is obvious. The result reads like a flowchart a loan officer could follow, which is why trees are loved in practice and are the building block of the strongest ensembles in Lecture 11.

~75 minTextbook ch. 9

Concept map

Recursive partitioning

Start with all training records in one box (the root). Then repeat:

  1. For every predictor and every possible split value, split the box in two and measure how pure the two halves are.
  2. Keep the single best split.
  3. Apply the same procedure inside each half, and so on, until a stopping rule is met.

The final boxes are leaves. A new record is dropped down the tree, and its leaf’s majority class (or average Y, for a regression tree) is the prediction. Because each split uses one variable, the boxes are always rectangles with edges parallel to the axes.

Grow a tree on income × credit-card spending700 bank customers with a graduate or advanced degree · 60% train / 40% validation

    
Depth 1: a single split on Income already lifts validation accuracy from the naive 89% to about 97%. Validation accuracy peaks around depth 3; push to depth 10 with leaf size 1 and tiny boxes chase individual customers: training accuracy climbs toward 100% while validation accuracy slips. Raise the minimum leaf size to see a simple fix.

  









Measuring purity


For a box where a fraction \(p_k\) of the records belong to class \(k\):


\[ \text{Gini} = 1 - \sum_k p_k^2 \qquad\qquad \text{Entropy} = -\sum_k p_k \log_2 p_k \]


Both are 0 for a pure box and largest for a 50/50 mix (Gini 0.5, entropy 1). A split is scored by the weighted average impurity of its two children; the best split gives the largest drop from the parent. Regression trees use the sum of squared deviations from the box mean instead.



  
A box has 90 non-acceptors and 10 acceptors. What is its Gini impurity?

  

  
0.18. 1 − (0.9² + 0.1²) = 1 − 0.82 = 0.18. It is fairly pure, but not perfectly, so the tree may still look for a split inside it.









Overfitting and pruning


Left alone, a tree keeps splitting until every leaf is pure. On the full bank data (all 11 predictors), the unpruned tree has 43 leaves, depth 10 and 100% training accuracy. Two remedies:


    
  
  • Stop early: limit depth, require a minimum number of records to split or per leaf, or require a minimum impurity decrease.
    • 
  
  • Grow then prune (preferred): grow a large tree, then cut back weak branches using cost complexity:
    • 



\[ \text{cost}(T) = \text{misclassification error}(T) + \alpha \cdot |\text{leaves}(T)| \]


Each α gives a different best subtree; choose α by cross-validation. In R’s rpart this is the complexity parameter cp; in scikit-learn it is ccp_alpha. The pruned bank tree has 15 leaves, and its validation accuracy (0.980) is slightly better than the full tree’s (0.979) with a third of the complexity.



  
Trees are called “unstable”. What does that mean in practice?

  

  
C. If two variables are nearly tied for the first split, a few records can flip the choice and everything below changes. High variance is the trees’ weakness, and Lecture 11 exploits it: averaging many different trees cancels it out.









Reading the tree: rules and importance


Every path from root to leaf is an IF–THEN rule. The top of the pruned bank tree:


IF Income ≤ 110.5 AND CCAvg ≤ 2.95                       → No loan   (the large majority)
IF Income > 110.5 AND Education = Undergrad AND Family ≤ 2 → No loan
IF Income > 110.5 AND Education = Undergrad AND Family ≥ 3 → Loan
IF Income > 116.5 AND Education ∈ {Graduate, Advanced}     → Loan


Variable importance adds up each variable’s impurity reductions across all its splits. Here: Education 0.38, Income 0.38, Family 0.17, CCAvg 0.05, and the rest near 0. The tree did its own variable selection.




StrengthsWeaknesses


Readable rules; no scaling needed; handles mixed types, interactions and nonlinearity; automatic variable selection; robust to outliers in XUnstable (high variance); axis-parallel boxes approximate diagonal boundaries poorly; a single tree rarely has the best accuracy







Code walk: a pruned tree for loan acceptance


Data: UniversalBank.csv.


Grow a full tree


library(rpart); library(rpart.plot)
bank <- read.csv("data/UniversalBank.csv")[, -c(1, 5)]
bank$Personal.Loan <- factor(bank$Personal.Loan)
set.seed(1); idx <- sample(nrow(bank), 0.6 * nrow(bank))
train <- bank[idx, ]; valid <- bank[-idx, ]
full <- rpart(Personal.Loan ~ ., data = train, method = "class",
              control = rpart.control(cp = 0, minsplit = 2, minbucket = 1))
sum(full$frame$var == "")          # number of leaves



import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.tree import DecisionTreeClassifier, export_text, plot_tree
bank = pd.read_csv("data/UniversalBank.csv").drop(columns=["ID", "ZIP Code"])
X, y = bank.drop(columns="Personal Loan"), bank["Personal Loan"]
X_train, X_valid, y_train, y_valid = train_test_split(X, y, test_size=0.4, random_state=1)
full = DecisionTreeClassifier(random_state=1).fit(X_train, y_train)
print(full.get_depth(), full.get_n_leaves(), full.score(X_train, y_train), full.score(X_valid, y_valid))



What you should see: depth 10, 43 leaves, training accuracy 1.0, validation ≈ 0.979.


What you should see: a large tree with dozens of leaves that fits the training data perfectly.




Prune by cross-validation


printcp(full)                          # xerror = cross-validated error for each cp
cv_tree <- rpart(Personal.Loan ~ ., data = train, method = "class",
                 control = rpart.control(cp = 0.00001, minsplit = 5, xval = 5))
best_cp <- cv_tree$cptable[which.min(cv_tree$cptable[, "xerror"]), "CP"]
pruned  <- prune(cv_tree, cp = best_cp)
rpart.plot(pruned, extra = 104)        # class, probability, % of records



from sklearn.model_selection import GridSearchCV, StratifiedKFold
alphas = full.cost_complexity_pruning_path(X_train, y_train).ccp_alphas[:-1]
grid = GridSearchCV(DecisionTreeClassifier(random_state=1), {"ccp_alpha": alphas},
                    cv=StratifiedKFold(5, shuffle=True, random_state=1)).fit(X_train, y_train)
pruned = grid.best_estimator_
print(pruned.get_n_leaves(), pruned.score(X_valid, y_valid))
print(export_text(pruned, feature_names=list(X.columns), max_depth=3))



What you should see: about 15 leaves, validation accuracy ≈ 0.98, sensitivity ≈ 0.86, much better than logistic regression’s 0.66 at cutoff 0.5.

Common pitfalls


    
  
  • Reporting the full tree’s training accuracy (100%) as performance.
    • 
  
  • Over-reading the tree’s structure. It is one of many plausible trees; refit on a bootstrap sample and the top splits may change.
    • 
  
  • Different importance definitions: R’s rpart includes surrogate splits; scikit-learn does not. Compare rankings, not raw numbers.
    • 
  
  • Coding categories as numbers in scikit-learn (Education 1/2/3) lets the tree split on order. That is acceptable for ordinal variables only; otherwise use dummies.
    •
