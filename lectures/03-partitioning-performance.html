Partitioning & Predictive Performance

A model that memorises its training data can look brilliant and predict terribly. Today we build the habit that protects every analysis in this course: hold data out, measure error where the model can’t cheat, and let cross-validation choose complexity.

~75 minTextbook ch. 2.5, 5.1–5.3

Concept map

Why we split the data

If we judge a model on the same records used to fit it, we reward memorisation. The fix is to split before modelling and give each part a single job:

PartitionTypical shareJobTouch it…
Training50–70%Fit model parameters (coefficients, splits, weights)As often as you like
Validation20–40%Compare models and tune settings (degree, k, λ)Many times, so it slowly becomes optimistic
Test (holdout)0–20%One final, unbiased estimate of performance for the chosen modelOnce, at the very end
You try 40 different models and pick the one with the lowest validation RMSE. Why is that RMSE still a little optimistic?

B. Choosing the best of many is itself a kind of fitting. That is exactly why a separate test set, used once, exists.

Overfitting, made visible

Below, 30 training points (●) and 30 validation points (○) come from the same smooth curve plus noise. Increase the polynomial degree: the curve hugs the training points ever more tightly. Watch what happens to error on the points it didn’t see.

Model complexity vs. errorsimulated data

Training error only goes down as degree rises. Validation error falls, bottoms out, then climbs: the classic U. The bottom of the U is the right complexity for this data. Rerun the split a few times: the best degree moves, which is why we prefer cross-validation.

Measuring prediction error

With validation residuals \(e_i = y_i - \hat y_i\) for \(i = 1,\dots,n\):

MetricFormulaUse it to…
ME (mean error)\(\frac1n\sum e_i\)Detect systematic over- or under-prediction (bias)
MAE\(\frac1n\sum |e_i|\)Report a typical error in the original units; robust to outliers
RMSE\(\sqrt{\frac1n\sum e_i^2}\)Penalise large errors heavily; the most common default
MAPE\(\frac{100}{n}\sum |e_i / y_i|\)Compare across scales (%); undefined if any \(y_i = 0\)
Two models have the same MAE (€1,000). Model A’s RMSE is €1,100 and model B’s is €2,400. What does that tell you?

C. RMSE ≥ MAE always, and the gap grows with the variability of error sizes. A big gap signals a few large misses, which matters if a single big error is costly.

Gains (lift) for numeric prediction

Sometimes we only need to rank records, for example which 10% of cars to prioritise. Sort validation records by predicted value and plot the cumulative actual value. The further the curve sits above the diagonal (random ordering), the better the ranking.

k-fold cross-validation

A single split wastes data and depends on luck. k-fold cross-validation splits the training data into k folds, fits k models (each leaving one fold out), and averages the k held-out errors.

With 10-fold CV used to compare 8 values of a tuning parameter, how many models are fitted in total (before the final refit)?

80. Each of the 8 settings is fitted 10 times. Then the best setting is refit once on all the training data. CV costs computation, which is why k = 5 or 10 is the usual compromise.

Code walk: honest error estimates for car prices

Data: ToyotaCorolla.csv.

Three-way split: 50 / 30 / 20

car <- read.csv("data/ToyotaCorolla.csv")
car <- car[, c("Price", "Age_08_04", "KM", "Fuel_Type", "HP", "Automatic",
               "Doors", "Quarterly_Tax", "Weight")]
car$Fuel_Type <- factor(car$Fuel_Type)
set.seed(1)
idx   <- sample(c("train", "valid", "test"), nrow(car), replace = TRUE, prob = c(.5, .3, .2))
train <- car[idx == "train", ]; valid <- car[idx == "valid", ]; test <- car[idx == "test", ]
sapply(list(train = train, valid = valid, test = test), nrow)

import pandas as pd, numpy as np
from sklearn.model_selection import train_test_split
car = pd.read_csv("data/ToyotaCorolla.csv")
cols = ["Age_08_04", "KM", "Fuel_Type", "HP", "Automatic", "Doors", "Quarterly_Tax", "Weight"]
X = pd.get_dummies(car[cols], drop_first=True, dtype=int); y = car["Price"]
X_tmp, X_test, y_tmp, y_test = train_test_split(X, y, test_size=0.2, random_state=1)
X_train, X_valid, y_train, y_valid = train_test_split(X_tmp, y_tmp, test_size=0.375, random_state=1)  # .375*.8 = .3
print(len(X_train), len(X_valid), len(X_test))

Compare error on each partition

fit <- lm(Price ~ ., data = train)
metrics <- function(actual, pred) {
  e <- actual - pred
  c(ME = mean(e), MAE = mean(abs(e)), RMSE = sqrt(mean(e^2)), MAPE = 100 * mean(abs(e / actual)))
}
rbind(train = metrics(train$Price, predict(fit, train)),
      valid = metrics(valid$Price, predict(fit, valid)))

from sklearn.linear_model import LinearRegression
fit = LinearRegression().fit(X_train, y_train)
def metrics(actual, pred):
    e = actual - pred
    return {"ME": e.mean(), "MAE": e.abs().mean(), "RMSE": np.sqrt((e**2).mean()),
            "MAPE": 100 * (e / actual).abs().mean()}
print(pd.DataFrame({"train": metrics(y_train, fit.predict(X_train)),
                    "valid": metrics(y_valid, fit.predict(X_valid))}).T.round(1))
What you should see: RMSE ≈ €1,250–1,450 on both sets and MAPE around 9–10%. For a simple linear model the gap between training and validation is small: it is not flexible enough to overfit much.

10-fold cross-validation

library(caret)

from sklearn.model_selection import cross_val_score, KFold
cv = KFold(n_splits=10, shuffle=True, random_state=1)
scores = cross_val_score(LinearRegression(), X_tmp, y_tmp, cv=cv, scoring="neg_root_mean_squared_error")
print(-scores.round(0), "mean RMSE:", round(-scores.mean(), 1))
What you should see: fold RMSEs ranging from roughly €1,100 to €1,800 around a mean near €1,350–1,370. A single validation split could have landed anywhere in that range.

Common pitfalls

  • Preprocessing before splitting. Computing means for standardisation or imputation on all data leaks validation information. Fit preprocessing on training data only.
  • Peeking at the test set to choose between models: then it is a second validation set.
  • No seed. Set set.seed() / random_state so results are reproducible.
  • Comparing models on different splits. Use the same partition (or the same CV folds) for every candidate.
  • Time-ordered data split at random. For forecasting, train on the past and validate on the future.

Validation data are for comparing and tuning; test data are reserved for the final estimate.
As model complexity increases, training error typically…
More flexibility can only fit the training data better (or equally well). Validation error is the one with the U-shape.
A model’s mean error (ME) on validation data is +€800. This means it…
e = actual − predicted; positive ME means actual values tend to be higher than predictions.
Which metric cannot be computed when some actual values are 0?
MAPE divides by y.
Main advantage of 10-fold CV over a single 70/30 split?
Averaging over folds reduces the dependence on one lucky or unlucky split.
