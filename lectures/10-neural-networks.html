Neural Networks

A neural network is a stack of logistic regressions feeding into each other. That stacking lets it bend decision boundaries into almost any shape, at the price of interpretability, tuning effort and a real appetite for overfitting. Today we open the box and train one live.

~80 minTextbook ch. 11

Concept map

One neuron

A neuron (node) takes inputs \(x_1,\dots,x_p\), forms a weighted sum plus a bias, and passes it through an activation function \(g\):

\[ \text{output} = g\!\left(\theta + \sum_{i} w_i x_i\right), \qquad g(s) = \frac{1}{1 + e^{-s}} \ \text{(logistic/sigmoid)} \]

With a sigmoid activation, a single neuron is logistic regression. Other common activations are tanh (range −1 to 1) and ReLU, \(\max(0, s)\), the default in deep learning.

Cheese tasting (TinyData): a hidden node has bias −0.3 and weights 0.05 on Fat and 0.01 on Salt. For a cheese with Fat = 0.2, Salt = 0.9, what does the node output (sigmoid)?

≈ 0.43. s = −0.3 + 0.05·0.2 + 0.01·0.9 = −0.281, and 1/(1 + e0.281) ≈ 0.430. This is exactly the first step of the textbook’s worked example. Every node in the network repeats it.

Architecture: layers of neurons

  • Input layer: one node per predictor, after scaling to [0, 1] and creating dummies.
  • Hidden layer(s): each node learns its own weighted combination of the inputs, a learned feature.
  • Output layer: one node for a binary or numeric outcome, or one per class (with softmax) for multiclass.

Parameters to learn: 2×3 + 3 biases + 3 + 1 bias = 13 here. With 12 predictors and 7 hidden nodes, it’s 12×7 + 7 + 7 + 1 = 99.

Training: backpropagation, live

Weights start small and random. For each batch of records, the network makes predictions (forward pass), measures the error, and sends that error backwards through the layers to compute how each weight contributed to it. Each weight then takes a small step downhill:

\[ w \leftarrow w - \eta \, \frac{\partial\, \text{Loss}}{\partial w} \qquad (\eta = \text{learning rate}) \]
Train a network in your browser2 inputs → hidden layer (tanh) → sigmoid output

XOR cannot be separated by one straight line, so logistic regression (1 hidden node) fails. Try 1 node, then 2, then 4. On “Two moons” with 10 nodes and decay 0, the boundary wraps around individual noisy points; raise decay to 0.1 and it smooths out. A learning rate of 1.0 can make the loss bounce instead of descend.

Tuning and practical rules

KnobEffectTypical choice
Hidden nodes (size)More nodes, more flexible boundary, more overfittingTune 1–10 by CV for tabular data
Weight decay (decay / alpha)L2 penalty on weights (ridge for networks); smooths the fitTune 0.0001–1 by CV
Input scalingUnscaled inputs saturate sigmoids and slow learningRescale to [0, 1] (min-max)
Epochs / stoppingToo many iterations overfitEarly stopping on validation loss
Random startDifferent seeds give different local optimaSet a seed; average several fits

On Universal Bank, 5-fold CV over size ∈ {1, 3, 5, 7} and decay ∈ {0.0001, 0.01, 0.1, 1} picks 7 hidden nodes with decay 0.1 (CV accuracy 0.982). The 1-node network gets stuck at 0.904, the naive rule. On the validation set the tuned network reaches accuracy ≈ 0.976, sensitivity ≈ 0.86 and AUC ≈ 0.98, the best so far. In the 2023 class project on breast-cancer data, a similar tuned single-layer network (5 nodes, decay 0.1) also won, with test accuracy 0.977.

The network outperforms the tree on accuracy. A loan officer asks why a particular applicant was rejected. Which model would you rather defend?

B. Accuracy is not the only criterion. In regulated settings such as credit, health and hiring, explainability can outweigh a point of accuracy. Post-hoc tools (variable importance, SHAP, partial dependence) help, but they are approximations.

Code walk: tune a network for loan acceptance

Data: UniversalBank.csv. A smaller practice set: accidentsnn.csv.

Scale to [0, 1] and tune size × decay

library(caret); library(nnet)
bank <- read.csv("data/UniversalBank.csv")[, -c(1, 5)]
bank$Education <- factor(bank$Education, labels = c("Undergrad", "Graduate", "Advanced"))
bank$Personal.Loan <- factor(bank$Personal.Loan, labels = c("No", "Yes"))
set.seed(1)
idx <- createDataPartition(bank$Personal.Loan, p = 0.6, list = FALSE)
train <- bank[idx, ]; valid <- bank[-idx, ]
grid <- expand.grid(size = c(1, 3, 5, 7), decay = c(0.0001, 0.01, 0.1, 1))
nn_fit <- train(Personal.Loan ~ ., data = train, method = "nnet",
                preProcess = "range",               # min-max scaling to [0, 1]
                tuneGrid = grid, maxit = 500, trace = FALSE,
                trControl = trainControl(method = "cv", number = 5))
nn_fit$bestTune; plot(nn_fit)

import pandas as pd
from sklearn.model_selection import train_test_split, GridSearchCV, StratifiedKFold
from sklearn.neural_network import MLPClassifier
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import MinMaxScaler
bank = pd.read_csv("data/UniversalBank.csv").drop(columns=["ID", "ZIP Code"])
bank["Education"] = pd.Categorical(bank["Education"].map({1: "Undergrad", 2: "Graduate", 3: "Advanced"}),
                                   categories=["Undergrad", "Graduate", "Advanced"])
X = pd.get_dummies(bank.drop(columns="Personal Loan"), drop_first=True, dtype=int); y = bank["Personal Loan"]
X_train, X_valid, y_train, y_valid = train_test_split(X, y, test_size=0.4, random_state=1, stratify=y)
pipe = make_pipeline(MinMaxScaler(), MLPClassifier(solver="lbfgs", max_iter=2000, random_state=1))
grid = GridSearchCV(pipe, {"mlpclassifier__hidden_layer_sizes": [(1,), (3,), (5,), (7,)],
                           "mlpclassifier__alpha": [0.0001, 0.01, 0.1, 1]},
                    cv=StratifiedKFold(5, shuffle=True, random_state=1), scoring="accuracy")
grid.fit(X_train, y_train)
print(grid.best_params_, round(grid.best_score_, 4))
What you should see: the best setting has 5–7 hidden nodes with moderate decay, and CV accuracy ≈ 0.98. Networks with 1 node do no better than the naive rule.

Common pitfalls

  • Unscaled inputs: slow or failed training.
  • No seed: results change from run to run; report the seed and, ideally, an average over several starts.
  • Tuning on the test set, or on training accuracy.
  • Too little data for the parameter count. A rough guide is at least 10 records per weight.
  • Assuming “deep” is better for tabular data. For spreadsheets, a well-tuned ensemble (L11) often wins.
