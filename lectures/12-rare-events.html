Rare Events & Imbalanced Data

Fraud, disease, churn, loan acceptance: the cases we care about are usually the rare ones. A model can be 99% accurate and catch none of them. Today we change both how we train and how we judge, so the rare class gets the attention it deserves.

~70 minTextbook ch. 5.5, 5.6

Concept map

The accuracy trap

When only a small share \(\pi\) of records are positive, the naive rule “predict negative for everyone” scores accuracy \(1 - \pi\) with sensitivity 0:

SettingPositive rateNaive accuracy
Personal-loan acceptance (Universal Bank)9.6%90.4%
Credit-card fraud (typical)0.2%99.8%
Rare disease screening0.05%99.95%

Worse, standard algorithms trained to maximise accuracy or likelihood learn to lean toward the majority class, because that is what pays. Three remedies, often combined:

  1. Judge correctly: sensitivity, precision, lift, AUC and, best of all, expected cost.
  2. Decide correctly: move the cutoff to reflect the costs.
  3. Train differently: rebalance the training data, or weight the classes.

Costs and the cost-optimal cutoff

Attach a cost to each kind of error: \(C_{FN}\) for missing a positive and \(C_{FP}\) for a false alarm. If a model outputs a well-calibrated probability \(p\), classifying a record as positive is worthwhile exactly when the expected cost of saying “no” exceeds the expected cost of saying “yes”:

\[ p \cdot C_{FN} \;>\; (1-p)\cdot C_{FP} \quad\Longleftrightarrow\quad p \;>\; c^* = \frac{C_{FP}}{C_{FP} + C_{FN}} \]
Missing a likely loan acceptor costs the bank about 10× as much as mailing an offer to someone who declines. What is the theoretical cost-optimal cutoff?

≈ 0.09. On the bank validation set, the empirically best cutoff for these costs is 0.10: total cost 419 vs. 665 at cutoff 0.5 and 1,920 for the naive rule. Sensitivity rises from 0.66 to 0.88.

Rebalancing the training data

TechniqueHowTrade-off
UndersamplingKeep all positives; randomly drop negatives until balancedFast; throws information away
OversamplingDuplicate positives (sample with replacement) until balancedKeeps all data; duplicates can encourage overfitting
SMOTECreate synthetic positives by interpolating between a positive and its nearest positive neighboursSmoother than duplication; can blur the class boundary
Class weightsKeep the data; weight each positive more heavily in the lossNo resampling noise; supported by most libraries
Two rules that must not be broken
  1. Rebalance the training set only. Validation and test sets must keep the real-world class mix, or every metric is distorted.
  2. A model trained on balanced data overstates probabilities: it believes positives are 50% common. Either re-adjust the probabilities to the true base rate or, more simply, choose the cutoff on the (unbalanced) validation set.

Oversampling and simply lowering the cutoff gave almost identical sensitivity and precision here. Why?

C. For many models, rebalancing and re-thresholding are two routes to a similar decision. Resampling matters more for algorithms that otherwise ignore the minority class during fitting, such as trees with minimum leaf sizes or kNN, and with extreme imbalance.

Code walk: rebalance and re-threshold

Data: UniversalBank.csv, prepared as in Lecture 8 (stratified 60/40 split).

Resample the training set only

library(caret)
bank <- read.csv("data/UniversalBank.csv")[, -c(1, 5)]
bank$Education <- factor(bank$Education, labels = c("Undergrad", "Graduate", "Advanced"))
bank$Personal.Loan <- factor(bank$Personal.Loan, labels = c("No", "Yes"))
set.seed(1); idx <- createDataPartition(bank$Personal.Loan, p = 0.6, list = FALSE)
train <- bank[idx, ]; valid <- bank[-idx, ]
x <- train[, names(train) != "Personal.Loan"]
up   <- upSample(x, train$Personal.Loan, yname = "Personal.Loan")     # oversample
down <- downSample(x, train$Personal.Loan, yname = "Personal.Loan")   # undersample
table(up$Personal.Loan); table(down$Personal.Loan)
# SMOTE: library(themis) recipes::step_smote(), or library(smotefamily)

import pandas as pd, numpy as np
from sklearn.model_selection import train_test_split
from imblearn.over_sampling import RandomOverSampler, SMOTE
from imblearn.under_sampling import RandomUnderSampler
bank = pd.read_csv("data/UniversalBank.csv").drop(columns=["ID", "ZIP Code"])
bank["Education"] = pd.Categorical(bank["Education"].map({1: "Undergrad", 2: "Graduate", 3: "Advanced"}),
                                   categories=["Undergrad", "Graduate", "Advanced"])
X = pd.get_dummies(bank.drop(columns="Personal Loan"), drop_first=True, dtype=int); y = bank["Personal Loan"]
X_train, X_valid, y_train, y_valid = train_test_split(X, y, test_size=0.4, random_state=1, stratify=y)
X_up, y_up = RandomOverSampler(random_state=1).fit_resample(X_train, y_train)
X_dn, y_dn = RandomUnderSampler(random_state=1).fit_resample(X_train, y_train)
X_sm, y_sm = SMOTE(random_state=1).fit_resample(X_train, y_train)
print(y_up.value_counts(), y_dn.value_counts())

Pick the cutoff that minimises cost

p <- predict(fit_orig, valid, type = "response")
actual <- valid$Personal.Loan == "Yes"
cost <- function(cut, cfn = 10, cfp = 1) {
  pred <- p >= cut
  cfn * sum(!pred & actual) + cfp * sum(pred & !actual)
}
cuts <- seq(0.01, 0.99, by = 0.01)
costs <- sapply(cuts, cost)
cuts[which.min(costs)]; min(costs)
plot(cuts, costs, type = "l"); abline(v = 1 / 11, lty = 2)

from sklearn.metrics import confusion_matrix
m = make_pipeline(StandardScaler(), LogisticRegression(max_iter=5000)).fit(X_train, y_train)
prob = m.predict_proba(X_valid)[:, 1]
def cost(cut, cfn=10, cfp=1):
    tn, fp, fn, tp = confusion_matrix(y_valid, (prob >= cut).astype(int)).ravel()
    return cfn * fn + cfp * fp
cuts = np.arange(0.01, 1.0, 0.01); costs = [cost(c) for c in cuts]
print("best cutoff:", cuts[int(np.argmin(costs))], " cost:", min(costs), " theory:", 1 / 11)
What you should see: a best cutoff near 0.10 (theory 0.091), cutting total cost by about a third compared with 0.5.

Common pitfalls

  • Resampling before splitting: duplicated positives land in both training and validation sets. That is leakage and wildly optimistic results.
  • Validating on balanced data: precision and accuracy no longer reflect reality.
  • Reporting probabilities from a balanced model as real-world risk without adjustment.
  • Inventing costs to hit a target. Get cost estimates from the domain, and show how the decision changes across a plausible range.
  • SMOTE on dummy variables: interpolation creates impossible values like 0.37 of a CD account. Use SMOTE-NC for mixed data.
