Ensembles: Bagging, Random Forests & Boosting

One tree is unstable; five hundred slightly different trees, averaged, are remarkably stable and accurate. Ensembles turn the trees’ weakness into a strength, and they are the method to beat on most tabular prediction problems.

~75 minTextbook ch. 13

Concept map

Why combining models works

Average \(B\) predictions that each have variance \(\sigma^2\) and pairwise correlation \(\rho\):

\[ \operatorname{Var}\Big(\tfrac{1}{B}\textstyle\sum_b \hat f_b\Big) = \rho\,\sigma^2 + \frac{1-\rho}{B}\,\sigma^2 \]

As B grows, the second term vanishes, but the first does not. Averaging helps most when the models are individually flexible (low bias) and weakly correlated. Two families of ensembles exploit this differently:

Parallel: bagging & random forests

Many deep, high-variance trees grown independently on resampled data, then averaged. Mainly reduces variance.

Sequential: boosting

Many small, high-bias trees grown one after another, each fixing what the previous ones got wrong. Mainly reduces bias.

Bagging = bootstrap aggregating

  1. Draw a bootstrap sample: n records sampled with replacement from the training data.
  2. Grow a deep (unpruned) tree on it.
  3. Repeat B times. Predict by majority vote (classification) or average (regression).
What fraction of the original records does a typical bootstrap sample leave out?

≈ 37%. The chance a given record is never drawn in n tries is \((1 - 1/n)^n \to e^{-1} \approx 0.368\). These out-of-bag (OOB) records act as a free validation set for each tree: averaging their OOB predictions gives an honest error estimate without a separate partition.

Watch the ensemble smooth outnoisy 1-D regression · deep trees vs. boosted stumps

Bagging: each faint line is one deep tree on a bootstrap sample. It is jumpy and overfits. The bold line is their average: as you add trees it becomes much smoother, and test error drops, then levels off. It never rises, so more trees don’t overfit. Boosting: each new stump (depth-1 tree) is fitted to the current residuals; the fit improves step by step. With a high learning rate and many trees, test error eventually creeps back up.

Random forests

Bagged trees are still correlated: if Income is the best first split, nearly every tree splits on Income first. A random forest decorrelates them by considering only a random subset of mtry predictors at each split (default √p for classification, p/3 for regression).

Boosting

AdaBoost (classification) reweights the training records after each tree, giving misclassified ones more weight so the next tree focuses on them. Gradient boosting generalises the idea: each new small tree is fitted to the residuals (more generally, the gradient of the loss) of the current ensemble, and added with a shrinkage factor (the learning rate):

\[ \hat f_m(x) = \hat f_{m-1}(x) + \eta \cdot \text{tree}_m(x), \qquad \text{tree}_m \text{ fitted to } y - \hat f_{m-1}(x) \]

Boosting has more knobs (number of trees, learning rate, tree depth) and can overfit if run too long, so tune by CV. Modern implementations (XGBoost, LightGBM, CatBoost) win many tabular-data competitions.

Code walk: forests and boosting for loan acceptance

Data: UniversalBank.csv.

Random forest with OOB error

library(randomForest)
bank <- read.csv("data/UniversalBank.csv")[, -c(1, 5)]
bank$Personal.Loan <- factor(bank$Personal.Loan)
set.seed(1); idx <- sample(nrow(bank), 0.6 * nrow(bank))
train <- bank[idx, ]; valid <- bank[-idx, ]
rf <- randomForest(Personal.Loan ~ ., data = train, ntree = 500, mtry = 3, importance = TRUE)
rf                                   # OOB error estimate + confusion matrix
plot(rf)                             # error vs. number of trees: flattens out
varImpPlot(rf, type = 1)             # mean decrease in accuracy

import pandas as pd
from sklearn.model_selection import train_test_split
from sklearn.ensemble import RandomForestClassifier, GradientBoostingClassifier
from sklearn.metrics import accuracy_score, recall_score, roc_auc_score
bank = pd.read_csv("data/UniversalBank.csv").drop(columns=["ID", "ZIP Code"])
X, y = bank.drop(columns="Personal Loan"), bank["Personal Loan"]
X_train, X_valid, y_train, y_valid = train_test_split(X, y, test_size=0.4, random_state=1)
rf = RandomForestClassifier(n_estimators=500, oob_score=True, random_state=1).fit(X_train, y_train)
print("OOB accuracy:", rf.oob_score_)
print(pd.Series(rf.feature_importances_, index=X.columns).sort_values(ascending=False).round(3))
What you should see: OOB accuracy ≈ 0.99, close to what the validation set will show. Income, Education, CCAvg and Family lead the importance ranking.

Gradient boosting

library(gbm)
train$y <- as.numeric(as.character(train$Personal.Loan))       # gbm wants 0/1 numeric
boost <- gbm(y ~ . - Personal.Loan, data = train, distribution = "bernoulli",
             n.trees = 1000, interaction.depth = 3, shrinkage = 0.1, cv.folds = 5)
best <- gbm.perf(boost, method = "cv")                           # optimal number of trees
prob_gb <- predict(boost, valid, n.trees = best, type = "response")
summary(boost, n.trees = best)                                   # relative influence

gb = GradientBoostingClassifier(n_estimators=300, learning_rate=0.1, max_depth=3,
                                random_state=1).fit(X_train, y_train)
for name, m in [("random forest", rf), ("boosting", gb)]:
    p, pr = m.predict(X_valid), m.predict_proba(X_valid)[:, 1]
    print(name, accuracy_score(y_valid, p), recall_score(y_valid, p), roc_auc_score(y_valid, pr))
What you should see: both ensembles reach accuracy ≈ 0.98–0.985 and AUC ≈ 0.997, the best results of the course so far on this data.

Common pitfalls

  • Boosting for too many rounds with a high learning rate: tune the number of trees by CV or early stopping.
  • Reading impurity importance as causal, or trusting it blindly: it favours continuous variables with many split points. Permutation importance is more reliable.
  • Forgetting the cost: 500 trees means 500× the scoring time and no single readable rule set.
  • Comparing models on different splits. Keep the partition fixed (or use the same CV folds) when building a comparison table like the one above.
